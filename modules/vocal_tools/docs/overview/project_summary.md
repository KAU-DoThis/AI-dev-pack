# Project Summary

## 1. Project Purpose

`vocal_tools` is a headless Python audio engine library.

It is designed to be imported by other projects that need audio separation, RVC conversion, audio mixing, model cataloging, and reusable cover-pipeline helpers. Suitable host projects include SHS GPU Node, SHS AI Tools, and other Python services.

This project is not a service or web application. It intentionally does not include FastAPI, a web UI, a database, a job queue, or hardcoded SHS integration.

## 2. Implemented Features

| Area | Current state |
| --- | --- |
| MDX | MDX ONNX separation implemented through catalog-driven `Separator` and `MDXOnnxEngine` |
| Demucs | Demucs separation implemented through `DemucsEngine`, including package-managed models |
| RVC | RVC conversion implemented through `RVCConverter` |
| Cover Pipeline | MDX -> RVC -> Mix pipeline implemented through `run_cover_pipeline()` |
| Audio Mixing | Vocal/instrumental mix implemented with alignment, gains, normalization, and WAV output |
| Catalog / Store | `ModelCatalog` and `ModelStore` implemented |
| Remote/User/Builtin Manifest | Builtin, user, and remote manifest loading implemented |
| RVC Voice Catalog | Local RVC voice model scanning implemented through `RVCVoiceCatalog` |
| Task Payload Helpers | JSON-safe task helpers and validation implemented |
| CLI | `vocal-tools` console script implemented |
| Docs | Usage, installation, API, CLI, testing, and release docs written |
| Tests | Standard-library `unittest` smoke tests added |
| VR Arch / MDXC Adapter | Adapter slots implemented with `external_cli` support; bundled backends not selected yet |

## 4. Public API Summary

Common imports:

```python
from vocal_tools import ModelCatalog, Separator
from vocal_tools import RVCVoiceCatalog
from vocal_tools import run_cover_pipeline
from vocal_tools import run_audio_separate_payload
from vocal_tools.rvc import RVCConverter
```

Recommended host-service boundary:

```python
from vocal_tools import (
    list_audio_models_payload,
    list_rvc_voice_models_payload,
    run_audio_cover_pipeline_payload,
    run_audio_rvc_convert_payload,
    run_audio_separate_payload,
)
```

See [the public API reference](../reference/public_api.md) for the full grouped API list.

## 5. CLI Summary

Representative commands:

```powershell
vocal-tools models list --models-dir test_models
vocal-tools models status --models-dir test_models
vocal-tools voices list --models-dir test_models
vocal-tools separate --models-dir test_models/mdx --model-id kim_vocal_2 --input input.wav --output-dir output/mdx
vocal-tools cover --models-dir test_models --input input.wav --output-dir output/cover --voice-model iut
```

During development, the module entrypoint is also available:

```powershell
python -m vocal_tools.cli --help
```

Model binaries are not package data. `test_models/` is a local development and verification fixture directory.

## 7. Installation Summary

Development install:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
python -m pip install -e ".[gpu]"
python -m pip install -e ".[demucs]"
python -m pip install "pip<24.1"
python -m pip install -e ".[rvc]"
```

Notes:

- RVC/fairseq has a known pip-version sensitivity; `pip<24.1` is documented for the verified local RVC install path.
- The `vocal-tools` console script is generated by `python -m pip install -e .`.
- Model files are not included in the package.
- The current base install is still heavier than ideal because it retains runtime dependencies for backward compatibility.

## 8. Using From Another Project

Install the local package from another project:

```powershell
python -m pip install -e H:/shs/modules/python/vocal_tools
```

Python usage:

```python
from vocal_tools import run_audio_cover_pipeline_payload

result = run_audio_cover_pipeline_payload({
    "models_dir": "test_models",
    "input_audio": "input.wav",
    "output_dir": "output/cover",
    "mdx_model_id": "kim_vocal_2",
    "voice_model": "iut",
})
```

Host projects should own API servers, queues, persistence, cancellation policy, auth, UI, and deployment-specific model placement.
